ChatGPT

PASO 18 — Revisión y aprobación editorial

Circuito formal de revisión humana: solicitud, devolución, reenvío y decisión editorial registrada. La aprobación no es automática.

PASO 18 implementado y desplegado
  1. Solicitud de revisión: el autor o responsable asignado envía el material.
  2. Devolución: reviewer, editor o admin pueden solicitar correcciones con fundamento registrado.
  3. Reenvío: tras corregir, el autor vuelve a solicitar revisión.
  4. Aprobación: solo editor o admin, hacia reviewed.
  5. Publicación: exige reviewed y aprobación humana registrada para la versión vigente.
  • No se puede aprobar si faltan formatos, hay desactualizados, control de calidad viejo o alertas críticas.
  • Si se modifica el contenido de una unidad revisada/publicada, vuelve a draft y rehace el circuito.

✅ Prueba transaccional completada (creación, seis formatos, solicitud, devolución, reenvío, aprobación, rechazo de transición directa, reapertura del circuito, ROLLBACK final).

Seguridad y trazabilidad

  • La asignación está protegida en la base de datos, no solo en la interfaz.
  • Los cambios directos de responsable, prioridad y vencimiento están bloqueados para usuarios sin rol editor/admin.
  • Los colaboradores asignados pueden editar contenido, fuentes, afirmaciones, evidencias y formatos.
  • Una solicitud de revisión vinculada a una versión anterior no puede aprobarse.

PASO 20 — SISTEMA DE NOTIFICACIONES EDITORIALES DE MADRE

Nueva etapa de desarrollo Continuidad del PASO 19

El objetivo de este paso es convertir a Madre en un sistema de trabajo editorial activo: cada integrante debe recibir avisos oportunos cuando se le asigna una tarea, cuando una producción requiere su intervención o cuando cambia el estado de una unidad editorial.

La notificación no debe ser solamente un mensaje informativo. Debe permitir identificar qué ocurrió, quién intervino, qué acción se necesita y a qué unidad editorial corresponde.

Principio rector: ninguna tarea editorial importante debe quedar dependiendo de que alguien entre manualmente a revisar la bandeja.

La implementación respetará la arquitectura existente: JavaScript modular, Supabase, Auth, RLS, historial y permisos por roles.
